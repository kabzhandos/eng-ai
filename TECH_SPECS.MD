\## Техническое задание на разработку веб-приложения «EngAI»



\### 1. Общее описание проекта



\*\*Название проекта:\*\* EngAI

\*\*Суть проекта:\*\* Веб-приложение для изучения грамматики английского языка с использованием генеративного искусственного интеллекта (LLM).

\*\*Главная ценность:\*\* Полный отказ от статических баз вопросов. ИИ генерирует уникальные задания в реальном времени, что исключает возможность зазубривания правильных ответов и заставляет ученика понимать саму суть грамматического правила.

\*\*Целевая аудитория:\*\* Ученики старших классов (уровни A1–B2), а также преподаватели, контролирующие процесс обучения.



\---



\### 2. Ролевая модель и доступы



Система использует ролевую модель доступа (RBAC):



\* \*\*Ученик:\*\* Проходит тестирование, решает задания, читает объяснения, видит свою и общую статистику.

\* \*\*Учитель (Ментор):\*\* Видит список своих учеников, детальную статистику каждого (особенно проблемные зоны), управляет группами.

\* \*\*Администратор:\*\* Управляет пользователями, темами, системными промптами для ИИ и мониторит нагрузку на API.



\---



\### 3. Функциональные требования



\*\*3.1. Модуль авторизации и регистрации\*\*



\* Регистрация/Вход по email и паролю, опционально — через Google/Apple ID (OAuth 2.0).

\* Привязка ученика к виртуальному классу или конкретному учителю по инвайт-ссылке или коду.

\* Создание профиля: Имя, класс, текущий подтвержденный уровень.



\*\*3.2. Модуль входного тестирования (Placement Test)\*\*



\* При первом входе система предлагает адаптивный тест для определения уровня от A1 до B2.

\* Тест включает грамматические конструкции разной сложности. В случае ряда ошибок алгоритм снижает сложность до выявления уверенного уровня владения.

\* По итогам теста пользователю присваивается стартовый уровень и открывается соответствующая ветка (дерево) грамматических тем.



\*\*3.3. Обучающий модуль и генерация заданий (Core Feature)\*\*



\* \*\*Дерево тем:\*\* Темы разбиты по уровням (например, A1: \*to be, Present Simple\*; B1: \*Conditionals 1/2, Present Perfect\*).

\* \*\*Генерация:\*\* При выборе темы бэкенд отправляет запрос к LLM (нейросети) с системным промптом, который содержит: текущий уровень ученика, тему, требуемый формат ответа (например, fill-in-the-blank, multiple choice, rewrite).

\* \*\*Градация сложности:\*\* По мере успешного выполнения заданий внутри одной темы, ИИ усложняет лексику и контекст предложений, оставаясь в рамках A1-B2.



\*\*3.4. Модуль «Работа над ошибками» (Smart Retry)\*\*



\* Если ученик отвечает неверно, система \*\*не дает\*\* ему тот же самый пример повторно.

\* \*\*Цикл отработки:\*\*

1\. ИИ генерирует понятное объяснение ошибки на родном языке ученика, опираясь на контекст конкретного предложения.

2\. ИИ генерирует \*абсолютно новое\* задание на это же грамматическое правило.

3\. Цикл повторяется до тех пор, пока ученик не даст правильный ответ (или серию правильных ответов).





\* Система фиксирует количество попыток, потраченных на усвоение темы (метрика «зависания»).



\*\*3.5. Модуль статистики и аналитики\*\*



\* \*\*Дашборд ученика (Индивидуальная статистика):\*\*

\* Текущий уровень (A1, A2, B1, B2) с прогресс-баром до следующего.

\* Тепловая карта или радар-чарт: соотношение правильных и неправильных ответов по конкретным темам.

\* История активности.





\* \*\*Глобальная статистика (Групповая/Геймификация):\*\*

\* Анонимизированный лидерборд (по желанию) или статистика потока/класса: «Ваш уровень выше, чем у 70% сверстников».

\* Общий процент усвоения тем внутри учебной группы.





\* \*\*Дашборд учителя:\*\*

\* Сводная таблица по классу (ФИО, Уровень, Активность).

\* \*\*Метрика «Зависания» (Bottlenecks):\*\* Подсветка красным цветом тем, где ученик потратил аномально высокое количество попыток (например, >5 генераций на одно правило). Это сигнал учителю для личного вмешательства.







\---



\### 4. Требования к ИИ-модулю (Промпт-инжиниринг)



Для стабильной работы приложения генерация должна быть строго структурирована.



\* \*\*Формат вывода:\*\* Нейросеть должна возвращать ответы исключительно в формате JSON (ожидаемые поля: `question`, `options`, `correct\\\_answer`, `rule\\\_explanation`).

\* \*\*Лексический контроль:\*\* В системном промпте должно быть жесткое ограничение — при генерации грамматических заданий для уровня A2, ИИ должен использовать словарь, не превышающий уровень A2, чтобы ученик не спотыкался о незнакомые слова, изучая грамматику.

\* \*\*Валидация:\*\* Бэкенд должен проверять полученный от ИИ JSON на целостность перед отправкой на фронтенд.

\### 5. Рекомендуемый стек технологий (Архитектура)



| Компонент | Технология | Обоснование |

| --- | --- | --- |

| \*\*Фронтенд\*\* | React.js (или Next.js) + Tailwind CSS | Высокая скорость разработки UI, отличная работа с динамическими данными и состояниями. |

| \*\*Бэкенд\*\* | Node.js (Express/NestJS) или Python (FastAPI) | Python идеален для быстрой связки с ИИ-моделями; Node.js отлично держит асинхронную нагрузку. |

| \*\*База данных\*\* | PostgreSQL | Надежное хранение реляционных данных (пользователи, статистика, логи ответов). |

| \*\*ИИ-Провайдер\*\* | OpenAI API (GPT-4o-mini) или Gemini API | Оптимальное соотношение скорости ответа, цены и качества генерации структурированного JSON. |

| \*\*Инфраструктура\*\* | Docker, Docker Compose | Удобство развертывания, контейнеризация всех модулей для легкого переноса на любой VPS/VDS. |



\---



\### 6. Нефункциональные требования



\* \*\*Производительность:\*\* Время ожидания нового сгенерированного задания не должно превышать 2-3 секунд. (Рекомендуется реализовать прегенерацию: пока ученик решает текущее задание, бэкенд асинхронно генерирует следующее).

\* \*\*Адаптивность:\*\* Интерфейс должен быть Mobile-First, так как школьники чаще всего будут использовать приложение со смартфонов.

\* \*\*Безопасность:\*\* Хранение паролей в хешированном виде (bcrypt), авторизация через JWT-токены, защита API от DDoS и Rate Limiting (чтобы избежать накрутки запросов к платному API нейросети).



Если потребуется детализировать структуру базы данных или составить примеры системных промптов для бэкенда — дай знать, подготовим архитектурный план.
